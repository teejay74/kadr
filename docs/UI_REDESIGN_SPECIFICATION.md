KADR — техническое задание на переработку пользовательского интерфейса

Версия: 1.0
Область: Frontend, Backend API, UX, видеоплеер
Приоритет: Высокий

1. Цель

Переработать существующий интерфейс KADR, сделав его максимально удобным для просмотра фильмов и сериалов.

В качестве ориентиров использовать:

* Apple TV — визуальный стиль, минимализм, крупные изображения.
* Netflix — удобную навигацию по сериалам и эпизодам.
* Stremio — возможность выбора источников воспроизведения.

Сохранить оригинальный стиль KADR: тёмная тема, фиолетовые акценты, современная типографика.

Основной принцип:

Пользователь выбирает фильм или серию и нажимает «Смотреть». Все технические операции KADR выполняет самостоятельно.

Информация о торрент-файлах, загрузках и буферизации не должна мешать основному сценарию просмотра.

⸻

2. Общая архитектура интерфейса

Реализовать единый подход для фильмов и сериалов.

Использовать общие компоненты:

* MediaHero — постер, фон, название и описание.
* MediaActions — основные действия с контентом.
* PlayButton — единая кнопка просмотра.
* SourceSelector — окно выбора источника.
* MediaPlayer — общий видеоплеер.
* PlaybackProgress — отображение прогресса.
* MediaStatus — состояние загрузки и доступности.
* CastCarousel — актёрский состав.
* RelatedMedia — похожие фильмы и сериалы.

Для сериалов дополнительно:

* SeasonSelector — выбор сезона.
* EpisodeList — список серий.
* EpisodeCard — карточка эпизода.
* NextEpisodeOverlay — переход к следующей серии.

Не дублировать логику воспроизведения между страницами фильмов и сериалов.

3.1. Верхний блок

Отображать:

* Постер.

* Год выхода.
* Рейтинг.
* Жанры.
* Продолжительность.

Разместить под описанием:

Основная кнопка:

* ▶ Смотреть — если просмотр ещё не начат.
* ▶ Продолжить с 01:24:35 — если есть сохранённый прогресс.

Дополнительные действия:

* Добавить в избранное.

Меню ⋯ должно содержать:

* Скачать фильм.
* Сохранить в библиотеку.
* Выбрать другой источник.
* Удалить загруженный файл — если он существует.

Удаление файлов должно требовать подтверждения.

3.3. Дополнительные разделы

Ниже основного блока:

1. Актёрский состав.
2. Похожие фильмы.
3. Дополнительная информация о фильме.

Не размещать технические блоки торрент-загрузок на основной странице.

4. Страница сериала

4.1. Верхний блок

Использовать тот же компонент MediaHero, что и для фильмов.

Показывать:

* Фон и постер.
* Название.
* Рейтинг.
* Год.
* Жанры.
* Количество сезонов.
* Описание.

4.2. Основная кнопка

Если сериал ещё не смотрели:

▶ Смотреть с первой серии

Если просмотр уже начат:

▶ Продолжить · Сезон 1, серия 6

Кнопка должна запускать соответствующий эпизод через общий механизм воспроизведения.

4.3. Список эпизодов

Разместить непосредственно под верхним блоком.

Не размещать его после технической информации о загрузках.

Структура:

Эпизоды — Сезон 1 ▼

Каждый эпизод отображается отдельной карточкой.

Карточка содержит:

* Изображение эпизода, если доступно.
* Номер.
* Название.
* Продолжительность.
* Прогресс просмотра.
* Статус доступности.

Возможные статусы:

Статус	Отображение
Не просмотрено	▶ Смотреть
Просмотрено частично	▶ Продолжить
Просмотрено полностью	✓ Просмотрено
Скачано	Значок сохранённого файла
Загружается	Индикатор загрузки
Ошибка источника	Предупреждение

Вся карточка эпизода должна быть кликабельной.

При нажатии KADR должен запускать просмотр или предлагать выбрать источник, если он необходим.

4.4. Выбор сезона

Реализовать удобный переключатель сезонов.

При повторном открытии сериала автоматически показывать сезон последнего просмотренного эпизода.

Не сбрасывать выбор на первый сезон при каждом посещении страницы.

4.5. Дополнительные действия

В меню ⋯ эпизода:

* Скачать серию.
* Сохранить в библиотеку.
* Выбрать другой источник.
* Удалить загруженный файл.

Для сезона предусмотреть:

* Скачать сезон.
* Сохранить сезон в библиотеку.

Операции с сезоном должны выполняться в фоне и отображать прогресс в разделе загрузок.

5. Единая логика воспроизведения

Реализовать общий механизм запуска просмотра для фильмов и эпизодов.

Frontend не должен самостоятельно выбирать конкретный торрент-файл на основе имени.

Решение о воспроизведении принимает Backend.

5.1. Сценарии

Сценарий A. Файл полностью скачан

1. Пользователь нажимает «Смотреть».
2. Backend находит локальный файл.
3. Проверяет его доступность.
4. Возвращает адрес воспроизведения.
5. Frontend открывает плеер.

Не выполнять повторный поиск через Prowlarr.

Сценарий B. Файл скачан частично

1. Пользователь нажимает «Смотреть».
2. Backend проверяет возможность потокового воспроизведения.
3. Если необходимые данные доступны — открывает плеер.
4. Если требуется буферизация — показывает состояние подготовки.
5. После подготовки начинает воспроизведение.

Не считать процент скачивания достаточным признаком готовности к воспроизведению.

Сценарий C. Источник выбран, но загрузка не начата

1. Использовать сохранённый источник.
2. Подготовить нужный файл.
3. Начать загрузку необходимых частей.
4. Запустить воспроизведение при готовности буфера.

Сценарий D. Источник отсутствует

1. Открыть окно выбора источника.
2. Выполнить поиск через существующий механизм индексаторов.
3. Предложить доступные варианты.
4. Сохранить выбор пользователя.
5. Начать воспроизведение.

Сценарий E. Источник недоступен

Показать понятное сообщение и предложить выбрать другой источник.

Не оставлять пользователя на бесконечном экране загрузки.

⸻

6. Окно выбора источника

Реализовать SourceSelector в виде модального окна.

Оно открывается только:

* Если источник ещё не выбран.
* Если пользователь самостоятельно выбрал действие «Другой источник».
* Если существующий источник недоступен.

6.1. Информация об источнике

Показывать:

* Качество: 720p, 1080p, 2160p.
* Тип релиза, если известен.
* Размер.
* Язык и озвучку, если известны.
* Количество сидов, если доступно.

Не показывать сырые технические названия торрент-файлов в основном списке.

Предусмотреть раскрываемый блок «Технические подробности».

6.2. Рекомендация

KADR может выделять рекомендуемый источник с учётом:

* Доступности.
* Качества.
* Размера.
* Предпочтений пользователя.

Не считать источник гарантированно работоспособным только на основании количества сидов.

6.3. Повторное использование источника

Если выбранная раздача содержит несколько эпизодов, сохранять связь между:

* Сериалом.
* Сезоном.
* Эпизодами.
* Торрентом.
* Файлами раздачи.

При переходе к следующему эпизоду повторно использовать подходящий источник.

Если сопоставление файла и эпизода неоднозначно, запросить подтверждение пользователя.

7. Единый видеоплеер

Использовать общий видеоплеер для фильмов и сериалов.

7.1. Основные функции

* Воспроизведение и пауза.
* Перемотка.
* Полноэкранный режим.
* Регулировка громкости.
* Отображение текущего времени.
* Отображение общей продолжительности.
* Отображение состояния буферизации.
* Возврат на страницу контента.

7.2. Прогресс просмотра

Сохранять позицию:

* Периодически во время просмотра.
* При паузе.
* При выходе из плеера.
* При завершении воспроизведения.

При повторном запуске предлагать продолжение с сохранённого момента.

Не считать эпизод просмотренным только из-за открытия плеера.

7.3. Аудиодорожки и субтитры

Предусмотреть выбор доступных дорожек и субтитров.

Показывать только те варианты, которые реально доступны для текущего файла и поддерживаются выбранным клиентом.

Не обещать переключение встроенных дорожек MKV в браузере, если используемый плеер этого не поддерживает.

7.4. Следующая серия

Для сериалов добавить кнопку:

▶ Следующая серия

При завершении эпизода показывать предложение перейти к следующему.

Предусмотреть настраиваемый автоматический переход.

Если следующий эпизод находится в уже выбранной раздаче, использовать её повторно.

Если следующая серия не готова, показывать буферизацию или понятный выбор источника.

⸻

8. Библиотека и скачанные файлы

Скачанные фильмы и эпизоды должны открываться через обычные страницы контента.

Не создавать отдельный сценарий «Открыть скачанный файл» для пользователя.

8.1. Библиотека

Разделить библиотеку на:

* Фильмы.
* Сериалы.

Для сохранённых материалов показывать обычные карточки с постерами.

При открытии фильма или сериала использовать единый интерфейс просмотра.

8.2. Временный кэш

Отличать временно загруженные данные от файлов, сохранённых в библиотеку.

Не удалять сохранённые файлы по правилам очистки временного кэша.

8.3. Удаление

Перед удалением файла:

1. Показать подтверждение.
2. Объяснить, что именно будет удалено.
3. Проверить, не используется ли файл активным воспроизведением.
4. Не затрагивать другие эпизоды или фильмы.

⸻

Главная · Фильмы · Сериалы · Новинки · Библиотека · Загрузки

* Активные загрузки.

* Состояние торрента.

Пользователь должен иметь возможность управлять загрузками, но эти действия не должны мешать обычному просмотру.

11. Требования к Backend API

Перед реализацией изучить существующие API KADR.

Не создавать дублирующие эндпоинты, если необходимые возможности уже реализованы.

При необходимости добавить единый механизм разрешения воспроизведения.

Пример проектируемого интерфейса:

POST /api/playback/resolve

Пример запроса:

{
  "media_type": "tv",
  "media_id": 12345,
  "season_number": 1,
  "episode_number": 6
}

Пример ответа:

{
  "status": "ready",
  "stream_url": "/api/stream/abc123",
  "resume_position_seconds": 1455
}

Возможные состояния:

* ready
* buffering
* source_required
* unavailable

Это проектируемый контракт. Перед внедрением сопоставить его с существующей архитектурой и выбрать решение с минимальными изменениями.

Не возвращать клиенту произвольные пути файловой системы сервера.

12. UX-требования

12.1. Минимум действий

Основные сценарии должны выполняться максимально быстро:

Скачанный фильм: открыть карточку → нажать «Смотреть».

Скачанная серия: открыть сериал → нажать на эпизод.

Следующая серия: нажать «Следующая серия» в плеере.

Продолжение просмотра: открыть сериал или фильм → нажать «Продолжить».

12.2. Понятные состояния

Не показывать пользователю технические сообщения вроде:

* Torrent metadata unavailable.
* Piece not downloaded.
* File index missing.

Вместо них использовать понятные сообщения с возможностью открыть технические подробности.

12.3. Загрузка и ошибки

Предусмотреть:

* Индикаторы подготовки воспроизведения.
* Тайм-ауты.
* Повторные попытки.
* Возможность отмены.
* Предложение сменить источник.

12.4. Визуальная согласованность

Все страницы должны использовать общие:

* Цвета.
* Отступы.
* Кнопки.
* Карточки.
* Модальные окна.
* Индикаторы.
* Состояния фокуса.

Не создавать отдельный визуальный стиль для фильмов и сериалов.

⸻

1. Запуск полностью скачанного фильма.
2. Запуск полностью скачанного эпизода.
3. Запуск частично загруженного файла при достаточном буфере.
4. Открытие выбора источника при его отсутствии.
5. Повторное использование сезонной раздачи.
6. Переход к следующей серии.
7. Сохранение позиции просмотра.
8. Восстановление позиции после перезапуска приложения.
9. Переключение сезонов.
10. Открытие сезона последнего просмотренного эпизода.
11. Обработка недоступного источника.
12. Удаление временного файла без повреждения библиотеки.
13. Работа интерфейса на компьютере.
14. Работа интерфейса на смартфоне.
15. Отсутствие регрессий в существующей загрузке и воспроизведении.

Добавить автоматизированные тесты для ключевой серверной логики и пользовательских сценариев.

⸻

14. Порядок реализации

Работу разделить на четыре последовательных подэтапа.

Подэтап A. Аудит

* Изучить существующие страницы фильмов и сериалов.
* Изучить API воспроизведения.
* Изучить механизм хранения прогресса.
* Проверить работу скачанных файлов.
* Подготовить план изменений.

Не начинать масштабный рефакторинг до завершения аудита.

Подэтап B. Общие компоненты

* Реализовать единый MediaHero.
* Реализовать MediaActions.
* Создать единые карточки и статусы.
* Переработать страницы фильмов и сериалов.
* Добавить удобный список эпизодов.

Подэтап C. Логика просмотра

* Реализовать единый запуск воспроизведения.
* Переработать выбор источников.
* Добавить повторное использование сезонных раздач.
* Обеспечить запуск скачанных файлов одним нажатием.

Подэтап D. Плеер и завершение

* Добавить продолжение просмотра.
* Реализовать переход к следующей серии.
* Перенести техническое управление в «Загрузки».
* Провести тестирование.
* Исправить выявленные проблемы.

После каждого подэтапа запускать тесты и предоставлять краткий отчёт.

⸻

15. Ограничения

1. Не переписывать работающий торрент-движок без необходимости.
2. Не менять существующую архитектуру хранения файлов без обоснования.
3. Не удалять пользовательские данные.
4. Не изменять Photodom.
5. Не выполнять развёртывание на Debian без отдельного разрешения.
6. Не изменять настройки VPN, маршрутизации и сетевой безопасности.
7. Не внедрять новые тяжёлые зависимости без необходимости.
8. Сохранять совместимость с существующими функциями KADR.
9. Не выполнять массовые изменения Backend API без предварительного анализа.
10. Все изменения должны сопровождаться проверками.

⸻

16. Критерии приёмки

Задача считается выполненной, когда:

* Фильмы и сериалы имеют единый визуальный стиль.
* Полностью скачанный фильм запускается одним нажатием.
* Полностью скачанный эпизод запускается одним нажатием.
* Пользователь не выбирает вручную MKV-файл при обычном просмотре.
* Для сезонной раздачи повторно используется выбранный источник.
