1. ОБЩАЯ ИНФОРМАЦИЯ

1.1. Название проекта

KADR

KADR — персональная медиаплатформа для поиска, потокового воспроизведения и хранения фильмов и сериалов.

Проект должен иметь собственную архитектуру, пользовательский интерфейс, API и систему управления медиаконтентом.

По функциональности ориентироваться на Stremio, по визуальному стилю — на Apple TV с отдельными элементами Netflix.

Прямое копирование интерфейса, логотипов, исходного кода или фирменных элементов существующих платформ не допускается.

1.2. Назначение

Создать персональный домашний онлайн-кинотеатр, позволяющий:

1. Просматривать каталог фильмов и сериалов.
2. Искать видеоконтент по названию.
3. Получать информацию о фильмах и сериалах из внешних каталогов.
4. Выполнять поиск доступных торрент-источников через подключённые индексаторы.
5. Выбирать качество и источник видео.
6. Начинать воспроизведение без ожидания полной загрузки файла, когда это технически возможно.
7. Перематывать видео и продолжать просмотр.
8. Сохранять выбранные фильмы и сериалы в локальную библиотеку.
9. Автоматически очищать временный кэш.
10. Смотреть видео на телевизорах, компьютерах и смартфонах.
11. Использовать сервис в домашней сети и удалённо через VPN.
12. Управлять пользователями, настройками и хранилищем.

Приложение должно работать полностью на собственном сервере пользователя.

Облачные сервисы могут использоваться для получения метаданных, постеров и другой вспомогательной информации, но не должны быть обязательны для воспроизведения уже сохранённого контента.

1.3. Ограничения использования

Система предназначена для личного использования и работы с контентом, на получение и воспроизведение которого у пользователя имеются необходимые права.

Интеграции с индексаторами должны учитывать их правила доступа и использования.

Не реализовывать обход авторизации, DRM, платного доступа, CAPTCHA или других механизмов защиты сторонних сервисов.

2. ЦЕЛЕВАЯ ИНФРАСТРУКТУРА

Проект будет развёрнут на существующем домашнем компьютере.

ОС	Debian 13
CPU	Intel Core i5-2500K
RAM	8 GB

Архитектура	x86_64
Режим работы	24/7

На сервере уже работает приложение Photodom, предназначенное для хранения и просмотра фотографий и видео.

Критическое требование: работа KADR не должна нарушать функционирование Photodom.

2.2. Изоляция приложений

KADR должен быть независимым от Photodom.

Требования:

* Отдельный каталог проекта.
* Отдельный Docker Compose.
* Отдельная база данных.
* Отдельные переменные окружения.
* Отдельные каталоги данных.
* Отдельная Docker-сеть.
* Отсутствие доступа к файлам Photodom без явного разрешения.
* Отсутствие конфликтов сетевых портов.
* Возможность перезапуска KADR без перезапуска Photodom.

Запрещается автоматически изменять существующую конфигурацию Photodom.

Перед развёртыванием необходимо проверить доступные порты, существующие сервисы и конфигурацию Docker.

Реализовать отдельный модуль Release Parser.

  "codec": "H264",
  "hdr": false

При невозможности достоверно определить характеристику возвращать null или unknown.

9. STREAMING MANAGER

9.1. Назначение

Streaming Manager — ключевой компонент KADR.

Он должен обеспечивать потоковое воспроизведение видео без обязательной полной предварительной загрузки.

9.2. Основные функции

* Подготовка видеопотока.
* Определение выбранного файла.
* Проверка готовности данных.
* Управление стартовым буфером.
* Обработка HTTP Range.
* Поддержка перемотки.
* Отслеживание состояния воспроизведения.
* Управление приоритетами загрузки.
* Обработка ошибок.
* Завершение стриминговой сессии.

9.3. HTTP Range

Реализовать поддержку:

Range: bytes=START-END

Корректно обрабатывать:

* 200 OK.
* 206 Partial Content.
* 416 Range Not Satisfiable.
* Content-Range.
* Accept-Ranges.
* Content-Length.

Не передавать клиенту байты, которые ещё не загружены.

Если нужный диапазон отсутствует, сервер должен дождаться его доступности в пределах установленного тайм-аута.

При превышении тайм-аута возвращать контролируемую ошибку.

9.4. Буферизация

Реализовать настраиваемый стартовый буфер.

Например:

STREAM_START_BUFFER_MB=32
STREAM_READ_TIMEOUT=30

Размер буфера должен корректироваться с учётом:

* Битрейта.
* Скорости загрузки.
* Скорости воспроизведения.
* Доступности частей файла.

Не считать фиксированный объём буфера гарантией непрерывного воспроизведения.

9.5. Перемотка

При перемотке:

1. Получить запрошенный диапазон.
2. Проверить наличие соответствующих данных.
3. Если данные отсутствуют, изменить приоритет загрузки.
4. Дождаться нужных частей.
5. Продолжить воспроизведение.

Учитывать, что отображаемое время фильма не всегда можно напрямую сопоставить с байтовым смещением.

Для некоторых контейнеров и кодеков потребуется информация об индексах, ключевых кадрах и структуре файла.

9.6. Форматы

Приоритетные форматы:

* MP4.
* H.264.
* AAC.

Дополнительные:

* MKV.
* H.265 / HEVC.
* AC3.
* EAC3.
* HDR.
* Внешние субтитры.

Поддержка дополнительных форматов зависит от возможностей клиентского устройства.

В MVP не обещать универсальное воспроизведение любого торрент-релиза.

9.7. Режимы воспроизведения

Предусмотреть интерфейс:

class PlaybackStrategy:
    async def prepare(self, media):
        ...
    async def get_stream(self, session):
        ...
    async def cleanup(self, session):
        ...

Реализации:

DirectPlayStrategy
RemuxStrategy

TranscodeStrategy зарезервировать для будущего развития.

Remux должен использоваться только в технически подходящих случаях.

Не запускать FFmpeg автоматически для каждого видео.

* При закрытии плеера.
* При завершении фильма.

11. БИБЛИОТЕКА

11.1. Режимы хранения

Предусмотреть три состояния:

STREAMING
CACHED
SAVED

STREAMING

Временная загрузка для воспроизведения.

CACHED

Видео находится в кэше и может использоваться повторно.

SAVED

Видео сохраняется в постоянной библиотеке.

Автоматическое удаление запрещено.

11.2. Сохранение фильма

При нажатии «Сохранить»:

1. Создать задачу сохранения.
2. Завершить загрузку выбранного файла.
3. Проверить целостность данных.
4. Добавить фильм в библиотеку.
5. Обновить статус.
6. Отобразить результат пользователю.

Если файл уже загружен, повторная загрузка не требуется.

11.3. Оптимизация хранения

По возможности использовать hard links вместо копирования.

Условия:

* Одна файловая система.
* Отсутствие конфликтов прав.
* Корректное управление жизненным циклом файлов.

Если hard link невозможен, использовать безопасное копирование.

Нельзя удалять исходный файл до подтверждения успешного завершения операции.

11.4. Структура библиотеки

├── cache/
├── library/
│   ├── movies/
│   └── series/
├── downloads/
└── metadata/

Пути должны задаваться через конфигурацию.

Не использовать жёстко прописанные абсолютные пути в бизнес-логике.

Автоматически контролировать временные файлы.

12.2. Правила очистки

Удалять в первую очередь:
